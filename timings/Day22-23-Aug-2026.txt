CI (Continuous Integration)
CD (Continuous Delivery/Continuous Deployment):

GitLab CI/CD
Introduction to GitLab CI/CD
Key Components in GitLab CI/CD
Pipeline: A sequence of stages executed in order. It defines the steps needed for building, testing, and deploying the code.
Jobs: Tasks that are run as part of the pipeline, such as compiling code, running tests, etc.
Stages: Logical grouping of jobs in a pipeline (e.g., build, test, deploy).
Runners: Agents that run the jobs. GitLab can use shared runners or custom runners configured by the user.

Pipeline Execution
1. GitLab automatically triggers the pipeline when you push changes to the repository.
2. The pipeline runs in the order of the defined stages.
3. Each job in a stage can depend on the output of the previous job, and if a job fails, the
pipeline halts.

Introduction to Jenkins CI/CD
Key Components in Jenkins CI/CD
1. Pipeline: The series of steps (jobs) that Jenkins will execute. These can be created using the Jenkins UI or by using a Jenkinsfile.
2. Jenkinsfile: A file that defines the pipeline script. It uses Declarative Pipelines or Scripted Pipelines to define the CI/CD process.
3. Jobs: Tasks within a pipeline, such as compiling code, running tests, and deploying the application.
4. Nodes and Executors: Jenkins runs jobs on specific machines known as nodes. Executors are the processes that run on these nodes.
5. Freestyle Projects: A simpler configuration for jobs but less flexible than Pipelines.

Pipeline Execution
1. Trigger: Jenkins pipelines can be triggered by events such as Git commits, scheduled times, or manual triggers.
2. Stages: Each stage runs sequentially unless parallel execution is defined.
3. Post Actions: Post-execution actions (such as sending notifications) can be defined in the pipeline

Common Concepts in CI/CD (GitLab(Repo) +
Jenkins(CI/CD))
1. Version Control Integration: Both GitLab and Jenkins integrate with Git (and other version control systems) to trigger pipelines based on code changes.
2. Automated Testing: Both platforms support running automated tests as part of the pipeline to catch bugs early in the development process.
3. Environment Configuration: Both support deployment to various environments (e.g., staging, production) after successful tests.
4. Artifact Management: You can store built artifacts (e.g., .jar or .zip files) and deploy them to different environments.

Best Practices for CI/CD
1. Use Branching Strategies: Feature branches, release branches, and main branches should all trigger different workflows.
2. Fast Feedback: Keep feedback loops fast. Break down your pipeline into smaller, faster jobs (e.g., unit tests first).
3. Environment Parity: Make sure the environments used for testing and production are similar to avoid "works on my machine" issues.
4. Keep Pipelines Efficient: Avoid unnecessary tasks. Run critical tasks first and avoid duplicating work.
5. Version Control Everything: Ensure that your pipeline configurations (.gitlab-ci.yml, Jenkinsfile) and deployment scripts are version-controlled.

Useful Plugins for Jenkins
GitLab Plugin: Allows Jenkins to receive GitLab webhook events.
Docker Pipeline: For integrating Docker into Jenkins pipelines.
JUnit Plugin: For reporting test results.
Slack Notification Plugin: For sending notifications to Slack after pipeline
completion.
