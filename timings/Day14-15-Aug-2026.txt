5. Kubernetes Node Maintenance
   - cordon
   - drain
   - uncordon

6. kubectl cordon
   - Prevents new Pods from being scheduled on the node
   - Existing Pods continue running
   - Used during node maintenance

7. kubectl drain
   - Prevents new Pods from being scheduled
   - Evicts existing Pods from the node
   - Used before node maintenance or upgrades

8. kubectl uncordon
   - Makes the node available for new Pod scheduling
   - Opposite of cordon

9. Cordon vs Drain vs Uncordon
   - cordon    -> Stop new Pods from being scheduled
   - drain     -> Evict existing Pods and stop new Pods
   - uncordon  -> Allow new Pods to be scheduled again

10. PodDisruptionBudget (PDB)
    - Protects applications during voluntary disruptions
    - Used during node maintenance and kubectl drain

11. PDB - minAvailable
    - Minimum number/percentage of Pods that must remain available

12. PDB - maxUnavailable
    - Maximum number/percentage of Pods that can be unavailable

13. minAvailable vs maxUnavailable
    - minAvailable   -> How many MUST STAY?
    - maxUnavailable -> How many CAN GO DOWN?

14. Deployment Rolling Update
    - How Kubernetes updates Pods
    - Old Pods vs New Pods

15. Deployment maxSurge
    - Number of extra Pods that can be created during an update

16. Deployment maxUnavailable
    - Maximum number/percentage of Pods that can be unavailable during an update

17. maxSurge vs maxUnavailable
    - maxSurge       -> How many EXTRA Pods can I CREATE?
    - maxUnavailable -> How many Pods CAN GO DOWN?

18. PDB vs Deployment maxUnavailable
    - PDB maxUnavailable
      -> Controls availability during voluntary disruptions

    - Deployment maxUnavailable
      -> Controls availability during rolling updates

19. minAvailable vs maxUnavailable vs maxSurge
    - minAvailable   -> How many MUST STAY?
    - maxUnavailable -> How many CAN GO DOWN?
    - maxSurge        -> How many EXTRA can I CREATE?
