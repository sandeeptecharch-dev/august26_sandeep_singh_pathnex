Kubernetes Topics

1. Node Uncordon
   kubectl uncordon node_name

   Uncordon is the opposite of cordon.
   It tells Kubernetes:
   "This node is ready again; you can schedule new Pods here."

2. PodDisruptionBudget (PDB)

   PDB protects your application during voluntary disruptions
   such as node maintenance or kubectl drain.

   Suppose you have 5 Pods:

   minAvailable: 3
   - At least 3 Pods must remain running/available.
   - Minimum number of Pods that must remain available.

   maxUnavailable: 2
   - Maximum number of Pods that can be unavailable.

   Example:
   replicas: 5
   minAvailable: 3

   Kubernetes will try to ensure that at least 3 Pods remain available
   during a voluntary disruption.

3. Deployment - maxSurge

   maxSurge is mainly used in a Deployment Rolling Update.

   Meaning:
   "During an update, how many extra Pods can I create above
   the desired number of Pods?"

   Suppose:
   replicas: 5
   maxSurge: 2

   Normally:
   5 Pods running

   During the update, Kubernetes can temporarily create 2 extra Pods:

   Old Pods:   5
   New Pods:   2
   Total:      7

   maxSurge
   - How many EXTRA Pods can be created during an update?

   maxUnavailable
   - How many Pods can be unavailable during an update?

4. minAvailable vs maxUnavailable vs maxSurge

   minAvailable
   - "How many MUST STAY?"
   - Used in PodDisruptionBudget (PDB)

   maxUnavailable
   - "How many CAN GO DOWN?"
   - Used in PDB and Deployment Rolling Update

   maxSurge
   - "How many EXTRA can I CREATE?"
   - Used in Deployment Rolling Update

5. Pod Identity vs IRSA - AWS EKS

   Both are ways to give a Kubernetes Pod permission to access
   AWS services without putting AWS access keys inside the Pod.

   Think:
   Pod needs S3
   ↓
   AWS needs to know:
   "Which Pod is allowed to access S3?"

   IRSA:
   Pod
   ↓
   Kubernetes ServiceAccount
   ↓
   IAM Role
   ↓
   AWS Service (S3)

   The Pod gets temporary AWS credentials through the Kubernetes
   ServiceAccount and IAM/OIDC configuration.

6. EKS Pod Identity

   EKS Pod Identity is the newer AWS-native approach.

   Pod
   ↓
   Kubernetes ServiceAccount
   ↓
   EKS Pod Identity
   ↓
   IAM Role
   ↓
   AWS Service (S3)

   Key idea:
   Both IRSA and EKS Pod Identity allow Pods to access AWS services
   securely without storing AWS access keys inside the Pod.
